# File Tracker - Memory Safety Case Study

> [!WARNING]
> This project (as well as its documentation) was generated using GitHub Copilot and later reviewed. It contains intentional bugs for educational purposes and for analyzing memory safety in C.

## Description

This project implements a file tracker in C that monitors changes to files in a specified directory. The code intentionally contains several memory safety bugs for educational and analysis purposes.

#### Environment Details

The project was analyzed, compiled, and executed on a _Linux_ system (Ubuntu 24.04.2 LTS). Therefore, all results refer to this environment. There is no guarantee that the code or the tools used will work properly on other operating systems or distributions.

## Compilation

### Buggy Version (for analysis)

```bash
gcc -o file_tracker main.c tracker_core.c utils.c -std=c11
```

### Debug Version with Symbols
```bash
gcc -g -O0 -o file_tracker_debug main.c tracker_core.c utils.c -std=c11
```

### Version with AddressSanitizer

```bash
gcc -fsanitize=address -g -O0 -o file_tracker_asan main.c tracker_core.c utils.c -std=c11
```

## Usage

```bash
# Basic monitoring
./file_tracker /path/to/directory

# With advanced options
./file_tracker -l changes.log -p '*.c' -p '*.txt' -i 3 -v /path/to/directory
```

### Options
-   `-l <logfile>`: Specify the log file (default: tracker.log)
-   `-p <pattern>`: Add a file pattern to monitor (e.g., *.c, *.txt)
-   `-i <interval>`: Monitoring interval in seconds (default: 5)
-   `-v`: Verbose output
-   `-h`: Show help

## Intentional Bugs Implemented

### 1. Out-of-Bounds Write

* **File**: `main.c`
* **Lines**: 27, 42
* **Description**: If there are more than 5 patterns or they are longer than 63 characters, the string copy exceeds the array bounds

### 2. Use-After-Free (UAF)

* **File**: `main.c`
* **Line**: 127
* **Description**: The `tracker` variable is used after being freed

### 3. Memory Leak

* **File**: `utils.c`
* **Lines**: 14–18
* **Description**: If `malloc()` for `info->path` fails, `info` is not freed even though the function exits

### 4. Out-of-Bounds Read

* **File**: `utils.c`
* **Line**: 55
* **Description**: If the file name is shorter than the extension being compared, reading may exceed the string bounds

### 5. Dangling Pointer

* **File**: `utils.c`
* **Lines**: 69–76
* **Description**: Not particularly relevant in this context, but in concurrent scenarios may lead to invalid values being used

### 6. Buffer Overflow

* **File**: `tracker_core.c`
* **Lines**: 14, 18
* **Description**: Command-line arguments written to limited-size buffers

### 7. Double Free

* **File**: `tracker_core.c`
* **Line**: 45
* **Description**: Clear double deallocation of `tracker->monitored_directory`

### 8. Dangling Pointer

* **File**: `tracker_core.c`
* **Line**: 56
* **Description**: After deallocation, the `tracker` pointer should be set to `NULL`

### 9. Out-of-Bounds Write

* **File**: `tracker_core.c`
* **Line**: 81
* **Description**: String copied into buffer without checking its length

### 10. Use-After-Free (UAF)

* **File**: `tracker_core.c`
* **Line**: 161
* **Description**: Print of removed element after its deallocation

### 11. Out-of-Bounds Write

* **File**: `tracker_core.c`
* **Line**: 194
* **Description**: String copied into a character matrix without bounds checking (on both dimensions)

### 12. Out-of-Bounds Write

* **File**: `tracker_core.c`
* **Line**: 216
* **Description**: String written into a buffer that is too small

## Tools Used for Analysis

### Static Analysis

```bash
# Cppcheck
cppcheck --enable=warning --inconclusive --std=c11 *.c

# Clang Static Analyzer
clang --analyze -Xanalyzer -analyzer-checker=core,security *.c

# Frama-C (GUI)
frama-c-gui -eva *.c
```

### Dynamic Analysis

```bash
# AddressSanitizer
clang -fsanitize=address -g -O0 -std=c11 -o file_tracker_asan main.c tracker_core.c utils.c

./file_tracker_asan /tmp

# Valgrind (Memory errors) - run on the debug version
valgrind --tool=memcheck --leak-check=full --show-leak-kinds=all ./file_tracker_debug /tmp
```
